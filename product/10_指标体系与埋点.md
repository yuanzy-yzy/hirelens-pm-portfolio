# 指标体系与埋点设计

版本：v0.1  
日期：2026-07-23

## 北极星指标

**有效初筛完成数**：在完成岗位画像确认后，系统成功生成可回溯证据且被 HR 完成人工复核的候选人报告数量。

该指标同时要求：

- 分析流程完成；
- 存在逐项证据；
- HR 实际查看并确认；
- 不以“模型调用次数”或“生成报告数”冒充产品价值。

## MVP 核心指标

### 流程指标

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 岗位画像完成率 | 完成画像确认的岗位数/开始创建的岗位数 | 记录基线，不提前虚构目标 |
| 简历解析成功率 | 成功得到结构化字段的文件数/上传文件数 | 测试集 ≥95% |
| 分析完成率 | 成功生成完整报告的简历数/进入分析的简历数 | 测试集 ≥95% |
| 报告复核率 | 被人工标记的报告数/已生成报告数 | 记录基线 |
| 导出成功率 | 成功导出的次数/点击导出的次数 | 测试集 100% |

### 模型效果指标

| 指标 | 定义 |
|---|---|
| 字段提取准确率 | 正确字段数/人工标注字段数 |
| 状态判断一致率 | 模型状态与人工金标一致的要求数/总要求数 |
| 证据引用正确率 | 引用确实支持判断的证据数/全部证据数 |
| 无依据判断率 | 没有原文证据仍给出肯定判断的数量/全部判断数 |
| 结构化输出成功率 | 通过 JSON Schema 校验的返回数/模型调用数 |
| 面试问题有效率 | 被人工认为可用于核验要求的问题数/问题总数 |

### 效率与成本指标

- 岗位画像生成耗时；
- 单份简历解析耗时；
- 单份匹配分析耗时；
- 人工复核耗时；
- 模型输入/输出 Token；
- 单份报告估算成本；
- 规则模式与混合模式的耗时差异。

## 关键事件

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `job_created` | 创建岗位 | job_id、input_type |
| `job_profile_generated` | 岗位画像生成 | requirement_count、clarification_count、duration_ms |
| `job_profile_confirmed` | HR 确认画像 | changed_count、required_count、bonus_count |
| `resume_uploaded` | 上传文件 | file_type、file_size_bucket、is_test_data |
| `resume_parsed` | 解析完成 | success、field_count、duration_ms、error_type |
| `match_started` | 开始分析 | mode、candidate_count、model_name |
| `match_completed` | 分析完成 | success、duration_ms、schema_valid、estimated_cost |
| `evidence_viewed` | 展开证据 | requirement_id、status |
| `judgement_corrected` | 人工修正 | old_status、new_status、error_category |
| `interview_question_used` | 复制或标记问题 | requirement_id、question_type |
| `report_exported` | 导出报告 | format、candidate_count、success |
| `data_deleted` | 删除数据 | scope、record_count |

## 分析原则

- 测试数据和真实业务数据必须分开；
- 未上线前只报告测试指标；
- 不使用候选人姓名、电话等敏感信息作为埋点属性；
- 所有百分比同时报告分子、分母；
- 小样本结果不宣称统计显著；
- 任何“效率提升”都需要人工基线对照。
